# DECISION FLOOD · Jev System One 实时决策大屏

一个把 Jev「不发文字、只做决定」这个卖点变成视觉洪流的演示大屏。面向短视频录制 / 对外宣讲。

**一句话概念**：所有 AI 都在写字，只有它在做决定。

---

## 跑起来 & 访问

### 方式一：双击启动（最省事）

双击 `jev-demo\start.cmd`。它会自动找到 Node、启动服务、并打开浏览器。

- **关闭那个黑窗口就是停止服务**（或在窗口里按 `Ctrl+C`）。
- 窗口里会打印实际访问地址，照那个地址打开即可。

### 方式二：命令行

```bat
cd jev-demo
node server.js --open
```

`--open` 会自动拉起浏览器；不加它就手动打开下面这个地址。

### 访问地址

```
http://localhost:8787
```

- **端口被占用会自动让位**：若 8787 已被占用（例如上次没关干净），服务会自动改用 8788、8789……**以窗口里打印的那一行为准**。
- **只监听本机**：服务绑定 `127.0.0.1`，同网段的其他机器访问不到。这是故意的 —— `/api/decide`、`/api/warmup` 会真实花钱，不能暴露给局域网。
- 停止：在运行窗口按 `Ctrl+C`。
- 已经开着？直接打开地址就行，不用重复启动。

### 环境要求

只需要 **Node 20+**，无任何第三方依赖（不用 `npm install`）。检查：`node -v`。

## 1. 三种运行模式

```bash
cd jev-demo
node server.js                 # A. 默认：有 .env 里的 key 就走 LIVE，没有就走 SIM
node server.js --open          # 同上，并自动打开浏览器
node server.js --warmup 200    # B. 预热回放池（唯一会批量调用 API 的命令，200 条实测约 80 秒、约 $0.005）
```

> `--warmup` 是命令行专用；HTTP 的 `/api/warmup` 单次硬上限 **200 条**（防止被误调用一次烧掉大量额度）。用 SIM 模式（无 key）跑预热会把模拟结果写进回放池，洪流幕会如实标成「模拟」而不是「回放」——不要用它生成对外演示的回放池。

- **SIM 模式**：没有 key 时自动启用，用本地模拟概率，视觉完整、**零调用**。
- **LIVE 模式**：`.env` 里有 `TYPESAFE_API_KEY` 就自动启用，实测台走真实调用。

> ⚠️ `.env` 里是明文凭证，已加入 `.gitignore`。**不要提交、不要分享**；如果 key 曾经在任何地方泄露过，先在 TypeSafe 控制台轮换再用。

右上角徽标显示当前模式：`SIM · 未配置 key` / `LIVE · 真实调用`。

> **API 消耗：默认零自动调用**（重要）
> 启动后不会自动花一分钱，三处都是「你不点，它不调」：
> - **洪流幕**：优先用 `data/replay.json` 的真实响应存档回放 → **0 调用**、节奏还稳；没有存档时用本地模拟数据补位，同样 **0 调用**。
> - **实测台（第二幕）**：进入时**不发起任何请求**，只等你粘贴文本后按 Ctrl+Enter 或点「判定这条」。每次判定 = 一次真实调用（约 $0.000025）。
> - **数据板（第三幕）**：纯静态展示，**0 调用**。
>
> 想要洪流幕也跑真实数据？控制条上点「**数据源：回放**」切到「**数据源：真实**」，洪流就会逐条真实调用 Jev（节奏跟着真实延迟走，每条约 0.3–2.5s，约 $0.000025/条）。切回「回放」即可恢复免费满帧。

## 数据从哪来 · 怎么验证它是真的

页面上每个决策都带来源标签，**绝不混算**：

| 来源标签 | 含义 | 会花钱吗 |
|---|---|---|
| **真实** | 本页面刚刚真实发出了 `POST /v1/systemone` | 约 $0.000025 / 次 |
| **回放** | 读 `data/replay.json` 的历史存档（洪流幕默认） | 否 |
| **模拟** | 无 key 时的本地模拟 | 否 |

三处可以互相印证，任何一处对不上都说明有问题：

1. **顶栏「真实调用 N 次」** —— 只统计真实发出的请求，回放和模拟都不计入。
2. **数据板「决策流水」** —— 保留最近 **300 条**完整档案（原文 + 三问概率 + 门禁 + 回执），容器内可滚动，标题直接标出「真实 N / 回放 N / 模拟 N」构成；**点任意一行弹出该次决策的完整详情**（原文、三问概率分布、门禁、回执）。刷新、切幕都不丢。
3. **「导出 CSV」** —— 一键把全部历史下载成表格文件（含每条的 confidence / anger / noul / 门禁 / 延迟 / token / 成本 / 原文），可用 Excel 打开逐条核对。
4. **运行服务的那个黑窗口** —— 每次真实调用打印一行，例如：
   ```
   [jev] 14:15:16  2583ms  599 in / 97 out  -> technical (conf 1)
   ```

想眼见为实：切到「数据源：真实」，洪流幕就会一条条真实打出去，黑窗口同步刷出上面的日志。

### 关于厂商对比数字（模块已移除）

数据板原先右栏有「厂商公开基准参考」（引自 TypeSafe 官方公开 demo，本机无法复现），**已于 2026-09-21 整体移除** —— 数据板上现在只保留本机真实实测的内容。底部计分板的「同量 LLM 估算」仍按官方 demo 口径（$0.01388/次）做同量折算，属参考值而非实测；不想要的话删掉 `index.html` 里 `sbLlm` 那一格和 `app.js` 的 `LLM_COST` 即可。

## 2. 三幕与操作

| 幕 | 快捷键 | 内容 |
|---|---|---|
| 一 · 洪流 | `1` | 事件持续涌入，Jev 逐条决策、按置信度三色分流，计分板实时累计（0 调用） |
| 二 · 实测台 | `2` | **粘贴你自己的一条评论/工单，Ctrl+Enter 实时判定**；也可点「随机一条」抽语料（按需调用） |
| 三 · 数据板 | `3` | 本机实测：真实调用次数 / 延迟分位 / 累计成本 + 决策流水回看与 CSV 导出 |

其他按键：`空格` 暂停洪流 · `速度 1×/2×/4×` 按钮调频 · `H` 隐藏控制条 · `F` 全屏。
实测台内：`Ctrl+Enter` 判定当前输入 · 点底部「最近判定」的 chip 可把历史文本填回输入框 · 焦点在输入框时全局快捷键自动让位，不会误触。

**URL 参数**（录制脚本里可直接用，省去手动切换）：

```
?scene=flood|slowmo|board     直接进入某一幕（跳过待机首页）
&static=1                     跳过打字机与过渡动画，直接给终态；实测台会自动真实跑一条用于定帧
&detail=N                     配合 scene=board：自动弹出第 N 条决策的详情（回看特写）
```

## 3. 短视频分镜脚本（约 80 秒）

录制前：全屏（F11），按 `H` 隐藏控制条，关掉其他标签页，OBS 录 1920×1080。

| 时间 | 镜头 | 画面 | 操作 |
|---|---|---|---|
| 0–4s | 冷开场 | 事件洪流满屏涌入，计数狂跳 | 洪流幕，速度切 4× |
| 4–14s | 全景 | 三条泳道分流，chip 不断落入 | 降回 1×，鼠标缓慢划过右侧泳道 |
| 14–24s | 核心特写 | 三问概率条展开，门禁亮灯 | 鼠标停在中央决策卡 |
| 24–32s | 转场 | 切到实测台 | 按 `2` |
| 32–52s | **主叙事** | 现场粘贴一条真实工单 → Ctrl+Enter → 三问揭示 + 门禁判定 | 输入框里打/贴内容，回车 |
| 52–62s | 对比第二条 | 换一条情绪激烈或信息残缺的，展示置信度掉下来 | 点「随机一条」或再粘一条 |
| 62–78s | 数据板 | 真实调用统计 + 决策流水回看 | 按 `3` |
| 78–84s | 收尾定格 | 「不发文字，只做决定。」 | 按 `1` 回洪流收尾 |

口播提示：实测台停留时重点讲三件事 —— **一次调用并行回答三个问题**、**输出是类型化结果不需要解析**、**置信度可以直接当门禁阈值用**。手输环节最能打消"是不是提前录好的"疑虑，建议留足镜头。

## 4. 结构

```
jev-demo/
├── start.cmd            # 双击启动（自动找 node + 开浏览器）
├── server.js            # HTTP 服务 + Jev 调用 + 门禁 + 模拟器（零依赖）
├── .env                 # TYPESAFE_API_KEY（明文，已 gitignore）
├── data/
│   ├── events.json      # 1000 条中文语料（真实感工单/评论/邮件/电话转写/弹幕）
│   └── replay.json      # --warmup 生成的真实响应存档（洪流幕回放用）
├── public/
│   ├── index.html       # 大屏骨架（三幕 + 控制条）
│   ├── style.css        # 浅色主题样式（配色集中在文件顶部 :root 变量，改一处即可全站换色）
│   └── app.js           # 三幕状态机与动画
└── shots/               # 预览截图
```

事件池构成（**1000 条，无重复**）：

| 渠道 | 条数 | 场景覆盖 |
|---|---|---|
| 工单 | 494 | 账单发票 / 退款 / 故障 / 账号安全 / 挽留 / 生产事故 / 物流 / 政务 / 容量配额 |
| 评论 | 216 | 应用商店与社区反馈，语气跨度最大 |
| 电话转写 | 138 | 口语化、信息零散、带语气词，最容易触发低置信度 |
| 邮件 | 105 | 商务采购 / 合规安全 / 集成对接 / 合作 |
| 弹幕 | 47 | 极短噪音与灌水（「1」「666」「签到」） |

语料刻意做了三档难度：**信息完整的标准件**（易，高置信度自动分流）、**信息残缺的口语件**（中，常见于电话转写）、**无意义噪音与紧急事故**（难，用来演示置信度门禁与人工兜底）。

服务端接口：

| 接口 | 说明 |
|---|---|
| `GET /api/status` | 当前模式、事件数、回放池大小、门禁阈值 |
| `GET /api/pool` | 事件池 |
| `POST /api/decide {text}` | 单条真实决策（慢镜头幕用） |
| `POST /api/flood-tick {n}` | 取 n 条洪流数据（优先回放池） |
| `POST /api/warmup {count}` | 预热回放池（单次上限 200 条） |

## 5. 三问与门禁（可调）

一次请求三个问题，并行评估同一份 state（`server.js` 的 `QUESTIONS`）：

- **Choice · 路由到哪个队列**：billing / technical / refund / sales / account / churn / noise（归档）
- **Score · 用户不满程度**：平静 → 不满 → 激烈 → 暴怒（4 档）
- **Noul · 需要人工立即介入？**：0–1 概率

> `noise`（灌水、测试、纯表扬、无关内容）是刻意加的第七档。官方建议「传完整候选清单，并留一个兜底选项，让模型能说『都不是』而不是硬挑最接近的」—— 没有这一档时，好评和「666」会被硬塞进业务队列，虽然置信度会掉到 0.3 并被门禁拦下，但画面上看着荒谬。

门禁（`GATE`）：Noul ≥ 0.8 有**优先否决权**直接转人工；否则 Choice 置信度 ≥ 0.85 自动执行、0.6–0.85 升级复核、< 0.6 转人工。

> ⚠️ 这套阈值是**演示用**的，不是可直接上线的业务规则。真实业务里阈值必须用你自己的数据校准（看「给 0.9 的那批里，实际对了几成」），别拿一个 0.9 就定自动执行。

## 6. 数据口径与诚实标注

数据板只呈现本机真实实测的内容（2026-09-21 起，厂商公开基准模块已整体移除）。所有数字来自每次响应的用量回执，可在运行服务的窗口里逐条交叉核对。

成本按官方定价 $0.042 / 百万输入 token、输出免费计算，取自每次响应的 `usage.input_tokens` 回执 —— 数据板里那四个数字是**本页面真实请求的累计值**。

> **两处成本口径不同，别混淆**：底部计分板的「**Jev 折算成本 / 同量 LLM 估算**」是按**已决策条数**折算出的对比值（含回放与模拟，这些并不花钱），只用于和 LLM 做同量对比；第三幕数据板的「**累计成本（真实调用）**」才是真实花出去的钱。演示时两个数字会差很多倍（回放幕跑的条数越多差得越多），这是正常的。
>
> 同理，**「决策流水」条数 ≠ 「真实调用次数」**：洪流幕读回放池，会往流水里写很多条却不产生任何调用。数据板上的流水标题已直接标出「真实 N / 回放 N / 模拟 N」的构成。

## 7. 常见改动

| 想改什么 | 改哪里 |
|---|---|
| 换主题色 / 切回深色 | `public/style.css` 顶部的 `:root` 变量（17 个色值，改这一处全站生效） |
| 换业务场景（审核 / 风控 / 工单） | `server.js` 的 `QUESTIONS` + `data/events.json` 语料 |
| 换分流颜色 / 文案 | `public/style.css` 的 `.lane-*`、`GATE_LABEL`（app.js） |
| 调洪流快慢 | `app.js` 的 `620 / state.speed`（基准间隔毫秒） |
| 改门禁阈值 | `server.js` 的 `GATE`（泳道标题会自动跟着变，无需改 HTML） |
| 关闭回放池、全部实时调 | 删掉 `data/replay.json`（此时洪流呈实时延迟，节奏会抖） |

## 8. 线上版（GitHub + Cloudflare Pages）

线上地址：

```
https://jev-demo.pages.dev
```

仓库：https://github.com/dailyoozoo/jev-demo

线上和本地是同一套页面。后端是 Cloudflare Pages Functions（`functions/api/`），不是 Node 进程：

| 能力 | 线上 |
|---|---|
| 洪流幕回放 | 读打包进去的 `data/replay.json`，0 调用 |
| 实测台真实判定 | 需要把 `TYPESAFE_API_KEY` 配成 Pages Secret；未配置则自动走模拟 |
| `/api/warmup` | **不提供**。公网开放预热接口会被刷额度 |
| 限流 | 每个 IP 每分钟最多 20 次真实调用（`/api/decide` 与真实洪流合计） |

部署（仓库根目录，已登录 Cloudflare）：

```bash
wrangler pages deploy public --project-name jev-demo
# 只做一次：把 key 写进 Secret，不进仓库
wrangler pages secret put TYPESAFE_API_KEY --project-name jev-demo
```

本地开发不受影响，仍然是 `node server.js`。`functions/` 只在 Cloudflare 上生效。
